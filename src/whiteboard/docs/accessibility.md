# Accessibility conformance report

The [WCAG 2.2 verification log](wcag-2.2-audit.md) records reproduced issues, separate fixes, and remaining checks. The [criterion coverage register](wcag-2.2-coverage.md) keeps all 55 Level A/AA criteria and their evidence gaps in scope. The assessment is still in progress; the baseline Supports entries below are not a completed WCAG 2.2 conformance claim.

- **Product:** Whiteboard (web application)
- **Standard:** WCAG 2.1 Level A and AA baseline, with a WCAG 2.2 Level A and AA assessment in progress.
- **Evaluation methods:** automated axe-core checks in the test suite on the library, editor, toolbars, and dialogs (organization settings, sharing, export, templates, facilitation and planning panels); scripted keyboard tests of every creation, editing, navigation, table, mind map, comment, and dialog flow; manual review of focus order, labels, and contrast in light and dark themes. Manual testing with screen readers (NVDA with Firefox and Chrome, JAWS, VoiceOver on macOS and iOS) is scheduled as part of the support process below and is not yet reflected in this report.
- **Terms:** Supports, Partially supports, Does not support, Not applicable. Under evaluation means the criterion assessment is incomplete.

## How the canvas is made accessible

The board is drawn on an HTML canvas. Every object on it also exists as a focusable item in a parallel accessible outline and in **Board objects**, named by type, lock state, and content (text, table cells, file names, or an image/drawing's alternative text). The outline and Board objects are each a single Tab stop, so Tab reaches the tools on any board; arrow keys, Home and End move between their items. Both lists give each frame, in its presentation order, followed by the objects it holds, then the objects outside frames, and Page Down and Page Up move to the next or previous frame; Board objects also sets a frame's objects in under it. Selecting an item there selects it on the board, brings it into view and returns focus to the board, where arrow keys move it and Enter opens its editor. Alt+F10 moves from the selection, or from the text being edited, to the selection's toolbar and back, so its actions are one key away rather than behind every other tool. Choosing Sticky note, Text, Rectangle, Ellipse or Frame in the tool rail with Enter or Space adds one in the middle of the view, as the tool's letter does, and opens a note or text for typing. Find on board searches all authored text. Frames provide a navigable structure (Frames and navigation, presentation mode, section links) for large boards. Dialogs, panels, and toolbars are native HTML controls.

## Accessibility features for collaboration

- Keyboard-operable facilitation (timer, voting, attention requests, presentation) and comments, including pin movement with arrow keys or labelled position fields.
- Follow a presenter or be brought to their view, with reduced-motion camera changes.
- Hide collaborators' cursors while keeping selection outlines.
- English and French interface, templates, help guides, and onboarding.

## Testing and support process

- Automated axe-core checks run on every change as part of the test suite; a failing check blocks release.
- Keyboard scripts cover creation, editing, navigation, sharing, and administration flows.
- Accessibility issues reported through Help and training feedback or the support channel are triaged within two business days; issues that block a task are prioritized as defects.
- Roadmap: complete manual screen reader testing and publish results; finish language tagging for secondary views; offer a keyboard alternative for freehand drawing (shape recognition from arrow-key strokes).
