# Whiteboard

A personal space to think, sketch, and plan. Built with vanilla JavaScript, HTML Canvas 2D, CSS, and Vite. Puter.js is the only backend. Boards can stay personal or be shared for simultaneous editing. Usage is measured with [Plausible](https://plausible.io), which counts page views and five product events (board created, shared, joined, exported, and workshop activity started) without cookies, personal data, or board content.

## Run

Requires Node.js 22.12+ (or a supported newer release).

```sh
npm ci
npm run dev
```

Vite prints the local URL. Use `npm run build` to produce `dist/`, and `npm run preview` to preview the production build. Deploy `dist/` to any static HTTP host, including Puter hosting. No separately hosted server, secrets, or environment variables are needed. Sharing a personal board asks for confirmation first, since it stays shared, then automatically deploys an app-scoped Puter worker to the owner’s account. The build includes its worker bundle.

The production app is hosted at [whiteboard.puter.com](https://whiteboard.puter.com/). `index.html` uses this address for its canonical URL, Open Graph metadata, social preview images, and structured data. `public/robots.txt` points crawlers to `public/sitemap.xml`, which lists the production homepage. Vite copies both files into `dist/` during the build.

## Features

- Rotate shapes, text, images, link/file cards, and drawings with the handle below the left corner, or use **Rotate selection** in the toolbar or command search for an exact angle. Shift snaps dragging to 15° steps; Escape cancels. Rotatable groups turn together, attached connectors follow, and ordinary undo, sharing, cropping, and exports retain the angle. Sticky notes, frames, tables, mind maps, and standalone connection lines remain upright.
- Drag a selection box to select touched objects, or enable **More tools → Selection settings → Precise selection** for 90% coverage. Tables and mind map nodes always use the 90% rule. Hold the mouse or a finger still briefly before dragging to use precise selection over a background object. Shift adds the earlier selection; Escape or pointer cancellation restores it. Preferences remain local and do not affect board history.
- Select an individual object inside a group by double-clicking/tapping it, pressing Enter on a selected group, or choosing **Select object in group**. Move, resize, rotate, edit, copy, duplicate, or delete that member while its siblings stay in place. Shift selects more members; Escape or **Select whole group** returns to the group. Ctrl/Cmd+Shift+Down/Up and command search provide keyboard access. A dashed group outline shows context, and group locks still protect every member.
- Filter a mixed selection by object type from its toolbar, More tools, or command search. Counts distinguish notes, text, shapes, lines, drawings, media, containers, mind map nodes, and groups. Whole groups remain intact; while editing inside a group, its members can be filtered by type. Selecting frames or mind map nodes retains their contents or branches. Filtering is local, preserves Undo/Redo, and works for viewers and protected selections.
- Workshop timer with presets, custom durations, pause/resume, +1/+5 minute extensions, reset, a minimized countdown, and presentation controls. Editors control the shared timer; viewers can follow along. Completion shows a visual alert and an optional device chime.
- **Facilitation** (canvas navigation next to the timer, More tools, or command search) runs structured workshops on shared and personal boards:
  - **Reactions**: thumbs up, heart, laugh, celebrate, idea, question, plus one, and eyes on board objects and comment messages. Counts appear as badges; hover or focus shows who reacted. Commenters and above can react; viewers see counts only.
  - **Live reactions** (the smiley in canvas navigation on a shared board): the same eight reactions float up the board for a moment for everyone present, with the sender's name unless anonymous input is on. Viewers can send them too, at most three a second; nothing is saved to the board or Undo history, and they need a live peer connection.
  - **Raise hand** (in the same popover): owners and facilitators see raised hands in the order they went up in **Participants** and the People tab, with a count on the participants button, hear each change through the screen reader, and can lower one hand or all of them. Everyone can lower their own; hands go down when the person leaves. Under anonymous input, other participants see only how many hands are up.
  - **Dot voting**: title, votes per person, one or several votes per object, all sticky notes, the selection, or objects in chosen frames, anonymous or named, results hidden until revealed, and an optional time limit, shown in the board timer unless it is counting down something else, that facilitators can extend by one or five minutes from the Voting tab. Participants vote by clicking the objects in the vote, as in Miro, or from badges on the canvas or an accessible list, and can remove votes; facilitators' clicks still select, so they can arrange the board mid-vote. Facilitators end the vote, reveal counts on objects and a ranked list, select the top results, and export CSV or JSON.
  - **Polls**: single or multiple choice, anonymous or named, results shown as an accessible bar list and exportable.
  - **Private mode** keeps each person's new sticky notes face down for everyone else until the facilitator reveals them all at once. **Anonymous input** removes names from new notes, reactions, and editing indicators. Both hide content and names in the app; they are not encryption (see [collaboration](docs/collaboration.md#facilitation)).
  - **Facilitator controls**: lock the board so participants can only add sticky notes, vote, react, and comment, or freeze all content; stage frames and reveal them one at a time; bring everyone to your view; and see who is present with their roles, change roles, or remove people.
  - **Agenda runner**: ordered frames become steps with optional durations and instructions saved on the board; frames saved as reusable content keep their steps, so a facilitator's own playbook inserts with its timings and instructions, or starts a new board with them. Starting or advancing moves everyone to the step, reveals its frame if it was staged or hidden, and starts the timer; participants see "Step 2 of 6: Brainstorm", and anyone who joins late or looks elsewhere can choose **Go to current step** in the Agenda tab.
  - **Summary**: attendance, contributions per participant (aggregate when anonymous), activity over time, most reacted and most voted objects, with CSV export. Completed votes and polls stay in the board's history.
- Follow a live collaborator from **Participants**. Someone not following anyone, such as a latecomer or someone who stopped, is offered to follow whoever presents, or whom others follow after **Bring everyone to me** or an agenda step, from a banner over the board. While they present, followers see only the current slide, cut off at its frame’s edge with plain space around it on other screen shapes, and move through the slides with them; stopping following, or the presentation ending, shows the board again. Editors can bring one participant or everyone to their view; viewers can follow. Pan, zoom, click the board, or press Escape to stop; opening a panel or dialog, changing a setting, or editing content does not. Incoming requests wait while you edit or use a dialog. Participant search, follower counts (also beside **Bring everyone to me** while presenting), and a local cursor visibility switch support workshops. Live navigation requires a peer connection and does not change board content or Undo history.
- Choose a line grid, dot grid, or no grid through **More tools → Grid and snapping** or command search. Optional grid snapping helps place, move, and resize objects while retaining precise keyboard nudges and numeric dimensions. Preferences stay on this device; snapped geometry uses ordinary undo and shared editing.
- Enable **More tools → Object dimensions** to inspect selected sizes and match another object's width or height while resizing. Paired guides mark equal dimensions; groups retain their proportions and exact numeric resizing remains precise.

- Shared boards with concurrent editing and typing, named live cursors, participant activity, who added each sticky note (in the object list, and on the notes with **Show sticky note authors** in Preferences or command search), invitations as a facilitator, editor, commenter, or viewer, for the whole board or a section of it, access management, local-only undo, and offline edit recovery.

- Project planning: task details (status, assignee, start and due dates, priority) on sticky notes, shapes, and text; **Task card** notes; a **Tasks** view with filters, grouping, a progress summary, and CSV/Excel export; a keyboard-accessible Gantt-style **Timeline** that can be placed on the board as an editable frame and refreshed from its tasks; dependency connectors; Kanban status sync; and Jira issue creation and status refresh on organization boards. See [Tasks and planning](#tasks-and-planning).
- Pinned board/object comments, threaded replies, author edits and recoverable deletion, resolve/reopen, search and filters, retained private drafts, and shared discussions. **Notifications** lists mentions, replies, and task assignments from every shared board's server: in the library sidebar, and from a board through **More tools** or command search, asked only when opened. The library's unread count is asked again when the window comes back into view, at most once a minute.
- Object links to a website or another board object, with canvas picking, searchable destinations, clickable badges, and copied direct URLs. Browser Back restores the source view. Personal URLs use this device’s saved boards; shared URLs require existing board access. Use Ctrl/Cmd+Alt/Option+Shift+K to edit a link and Ctrl/Cmd+Alt/Option+Shift+C to copy the selected object’s URL.
- Personal library with search, favorites, sorting, rename, duplicate, and recoverable local deletion through Trash. Search matches board names and what the boards hold (text, table cells, link and file names, tags), ignoring case and accents; boards whose names match come first, and a board found by its content shows the object and words it was found in, and opens with Find on board showing the first match. What a workshop keeps from someone is never matched for them.
- Blank boards and a searchable library of 58 bilingual templates in nine categories, reusable components, a pictogram and sticker library, and reusable content saved from a selection. See [Templates and content libraries](#templates-and-content-libraries).
- Infinite canvas with zoom, fit, pan, and mouse, pen, and touch pointer input. Auto-detect, Mouse, and Trackpad preferences control wheel navigation; right/middle/Space-drag pans, touchscreen pinch zooms, and long-press selects multiple objects.
- Minimap (M) with a live geometry overview, click-to-jump, draggable viewport, keyboard pan/zoom, and Fit board. Visibility is remembered on this device; camera navigation preserves selection and history and is available to viewers.
- Find on board with type filters, full text/table/link/file-name search, persistent results, canvas highlighting, and keyboard navigation.
- Command palette with Ctrl/Cmd + K, a header button, and More tools. Search creation, formatting, arrangement, navigation, export, and history commands, reopen a local board by name, or go to one of the open board's frames by its name (as a step Back undoes). Arrow keys navigate, Enter runs, and Escape closes. Unavailable commands explain their selection, lock, capacity, or permission requirements; English and French names and aliases are searchable.
- Sticky notes, text, rectangles, ellipses, directional arrows, freehand drawing, frames, and PNG/JPEG/WebP images (GIF and BMP files are added as a PNG copy, a GIF as its first frame). With a mouse, pen, or finger, click or tap to place a sticky note, rectangle, ellipse, or frame at its default size centred on the click (text starts at the click), or drag to draw it at a size (Shift keeps it square; two fingers still pan and zoom); dragged text takes the width and keeps growing with what is typed, and a frame drawn around objects takes them in. The eraser end or eraser button of a stylus rubs out the drawings it passes over, whatever tool is active, in one undo step.
- Nondestructive image cropping with on-board handles, exact pixel controls, aspect ratios, oval masks, alignment guides, and restoration of the original image. Crops persist through resizing, clipboard, exports, undo/redo, and collaboration.
- Shape library (S) with 70 searchable shapes in families: basic shapes, flowchart (document, multiple documents, predefined process, manual input and operation, delay, display, off-page connector, or, summing junction, preparation, data, internal storage, merge, extract, database), architecture and data flow (cloud, server, database, queue, user or actor, mobile device, laptop, browser window, firewall, load balancer, API, container, data store), service blueprint and journey (touchpoint, pain point, positive/neutral/negative emotion, lane header), BPMN (start, intermediate and end events, task, subprocess, exclusive/parallel/inclusive gateways, data object), UML (class, actor, note, package), and wireframe components (button, text input, checkbox, radio, toggle, dropdown, search bar, navigation and tab bars, card, image placeholder, avatar, modal, browser, phone and tablet frames, slider, progress bar, pagination, text placeholder). Choosing a shape with the pointer arms the rectangle tool with it: click to place it at its default size or drag to draw it, as in Miro; from the keyboard it is added in the middle of the view, or beside what is already there, as are sticky notes, text, and shapes added with their shortcuts or command search, and tables, links, and files added from More tools, so notes several people add at once sit side by side. Change shape on the selection toolbar converts shapes, notes, and text in place while retaining content, formatting, groups, and connections. Silhouettes have safe label areas and connectors that attach to their visible outlines.
- Connection lines with straight, elbow, and curved paths; solid, dashed, and dotted strokes; adjustable thickness; independent ends (arrowhead, filled or open triangle, filled or open diamond, dot, open circle, and ERD bar and crow's foot for UML, BPMN, and entity relationship diagrams); and multiline text labels. Draw between objects with the Arrow tool, reconnect by dragging either round endpoint, or choose endpoints with the keyboard.
- **Add content** at the foot of the tool rail opens tiles beside it for what the rail's own tools do not add: tables, links, files, mind maps, embeds, task cards, bulk sticky notes, components, and icons and stickers, each doing what its More tools entry does. Arrow keys move between the tiles. On phones the rail keeps to two rows and these stay in More tools.
- Quick diagram creation: select a shape, sticky note, or text box and use its four blue handles. Hover or focus to preview; click to connect a nearby object or add a matching blank object with an arrow. Drag a handle to choose another target or create a free endpoint. Creation respects locks, avoids occupied placements, and undoes in one step.
- Direct text editing on the canvas. New notes and text boxes are ready to type; double-click or press Enter to edit existing text. Ctrl/Cmd + Enter or Done saves; Escape cancels; Enter adds a line. On a sticky note, Tab or Ctrl/Cmd + D saves it and goes on to a new note of the same size and color beside it (Shift + Tab to the left), at the next free spot; in a list, Tab still indents.
- Clear content from selected sticky notes and shapes with Ctrl/Cmd + Backspace, the eraser on the selection toolbar, More tools, or command search. Text and tag assignments are removed in one undo step; colors, typography, dimensions, positions, groups, object links, and connections remain. A selected member inside a group clears independently. Plain text boxes, tables, frames, mind-map nodes, and external-content cards are unaffected. While typing, native text deletion shortcuts still apply. Clearing already-empty objects preserves Redo.
- Vertical text alignment for sticky notes and shapes: top, middle, or bottom, next to the horizontal alignment in the text toolbar. New sticky notes, rectangles, and ellipses start with their text centred both ways, as in Miro; notes saved before keep their text at the top, and library shapes stay centred. The alignment survives copying styles, shared editing, undo, exports, and Miro imports (Miro's own vertical alignment is kept).
- Automatic text fitting for sticky notes and shapes. Auto-fit shrinks text as you type or resize, using the chosen font size as the maximum and 8px as the minimum. It is enabled for new sticky notes and can be toggled for selected notes and shapes; existing saved layouts keep their setting. A message identifies text that still needs a larger object. Canvas editing, exports, and collaborators use the same fitted layout.
- Automatic height for plain text added on the canvas, pasted from other apps, or converted from shapes. Text grows or shrinks as you type and rewraps when its width or typography changes. Auto height can be toggled for existing text; saved manual layouts keep their dimensions. Numeric and corner resizing change width, with height calculated from the content. Long-text editing keeps the caret visible, and connectors, exports, undo, and shared editing follow the derived bounds.
- Font-family selection for notes, text, shapes, frames, and connector labels: DM Sans, Noto Sans, EB Garamond, Roboto Mono, and Caveat. Choose a family in the text toolbar or command palette; it applies to each selected text object while retaining character emphasis, links, and lists. Families survive shared editing, undo, style copying, shape conversion, and saving. Fonts are bundled locally and loaded when needed; exports wait for their fonts before measuring text.
- Quick duplication: hold Alt/Option before dragging to place a copy, or use Alt/Option + arrow keys to duplicate beside, above, or below the selection with a 24-unit gap. Directional commands are also available in the command palette. Groups, frames, rich content, and connections between copied objects stay together. Each copy is one undo step; Escape cancels a copy drag. To bypass snapping on an ordinary move, press Alt/Option after starting the drag.
- Copy and paste object styles from the selection toolbar, More tools, or command palette. Ctrl/Cmd + Alt/Option + C copies one object’s appearance; Ctrl/Cmd + Alt/Option + V applies compatible settings to the selection in one undo step. Fill/stroke color, text formatting, auto-fit, and connector path/stroke/caps are supported. Mixed text uses the first character’s appearance. Destination text, links, lists, shape, dimensions, and attachments are retained; automatic text height still follows typography. Copied styles stay available across boards, reloads, and tabs on this device.
- Inline text links: select words and use the link button or Ctrl/Cmd + Alt/Option + K; pasting a web URL over selected words also links them. At an empty caret, a pasted URL becomes linked text. Edit or remove a link without losing its label or other formatting. Click linked canvas text for a destination preview, or use **Text links** for keyboard access, including on locked objects and shared viewer boards. Opening a destination uses a new tab. Links survive shared edits, undo, copying, shape conversion, saving, and raster exports; Find also searches their URLs. HTTP and HTTPS links are supported.
- Bulleted and numbered lists with nesting, hanging indents, and automatic numbering. Open **Lists** in the text toolbar; Tab/Shift+Tab changes indent, Shift+Enter continues the same item, and Enter on an empty item outdents or finishes the list. Typing `- `, `* `, `1. `, or `1) ` at the start of a paragraph starts a list. Lists work with partial formatting, fitting, automatic height, undo, copying, exports, and shared editing. Pasting HTML lists retains nesting; copying text includes readable markers and semantic HTML. Custom numbering starts/styles are not yet supported.
- Select words while editing to apply bold, italic, underline, strikethrough, text color, or highlighting. Toolbar controls retain the text selection; Ctrl/Cmd + B/I/U also work, and a caret-only toggle styles the next text you type. Rich text supports undo/redo, internal copy/paste, and simultaneous shared editing. Font size and alignment affect the whole object. Outside text editing, formatting applies to selected objects. Styles survive saving, duplication, shape conversion, and exports. Object properties retains exact width/height editing.
- Right-click an object or the empty board, or press Shift+F10 or the context menu key, for a menu of what applies there: copy, cut, paste at that spot, duplicate, delete, layer order, group, lock, styles, copy as image, the object's link, comments, select all, and undo/redo. A right-click selects the object under the pointer unless it is already selected; a right-drag still pans. Pasting from the menu reads the system clipboard, which the browser may ask permission for.
- Move, resize, recolor, multi-select, duplicate, and delete objects. Every corner resizes, keeping the opposite corner in place (also on rotated objects); a single shape, text box, frame, card or drawing also resizes from the middle of each side, one dimension at a time, while sticky notes and images keep to their corners and auto-height text resizes only across. Snapping and the grid apply to the right and bottom edges. Group objects, align on all six edges/centers, distribute with equal horizontal or vertical gaps, and change layer order. Give rectangles, ellipses and outlined library shapes a dashed or dotted border, such as a trust boundary, or a thicker one for emphasis from **Border** in the selection toolbar; the border grows inward, so connectors still meet its outer edge. Connect shapes with arrows that follow their endpoints. The selection toolbar floats beside the selection on larger screens, keeps the frequent actions in its row and the rest under **More options**, stays clear of the quick-connect handles and open panels, hides while you drag, and docks under the header on phones.
- Logical frames with contained objects, frame navigation and ordering, frame formats for slides (16:9, 4:3, 1:1), printed pages (A4, Letter), and screens (phone, tablet, desktop) chosen beside the Frame tool, as in Miro (a click or F adds a frame of that size, and dragging still draws any size) or for a frame on the board in **Resize frame**, frames that nest (a frame lying wholly inside a larger one moves, copies, and is deleted with it, as in Miro), and a presentation mode for frames, a selection, or the whole board. **Frames and navigation** is a side panel, like Find on board, that stays open while you go from frame to frame (each a step browser Back undoes, with the address linking to that frame, as object links do), marks the frame in view, and follows changes to the frames as they are made, by you, undo, or collaborators; it lists the frames in presentation order with how many objects each holds (nested frames included; a long title takes at most two lines and shows in full on hover), indents a frame lying within another under it, copies a link to any frame from its row, and is one Tab stop moved through with the arrow keys, Home and End, Alt+Up/Down moves the focused frame earlier or later (the order arrows and that hint are offered only to people who may change the board, and not on a locked frame), a board with more than seven frames can search them by title (an untitled frame is named by its place, "Frame 3", and found by that name), and **Add frame** adds the next slide to the right of the last one, at its size, and goes to it. Zoomed out, where a frame's own title would be too small to read, the frame is named above its top-left corner at a fixed size, as in Miro; a click on the name selects the frame and a drag moves it. A name that would overlap another, as a nested frame's near the corner of the frame around it, is left out until zooming in parts them, the larger frame keeping its name.
- Editable link cards, tables (up to 20 rows by 12 columns) with direct cell editing, range selection, spreadsheet clipboard, row/column insertion and deletion, individual row/column sizing, and whole-table text formatting (font size and family, bold, italic, and left/centre/right alignment, with rows growing to fit), plus downloadable file attachments.
- Mind-map authoring with on-canvas plus buttons, keyboard child/sibling creation, automatic layout, four directions, curved/straight branches, reassignment, collapse/expand, branch ordering, and editable node styles. The mind-map template now creates a real hierarchy.
- System copy/cut/paste across boards and browser sessions, with editable object relationships and plain text for other apps. Paste external text, a URL as a link card (or, for supported services, an embed), or clipboard images.
- Copy selected objects, groups, or frames as a PNG image using the selection toolbar, More tools, or Ctrl/Cmd + Shift + C. Includes a preview/download fallback when browser clipboard access is unavailable.
- Create sticky notes in bulk with Shift + N or More tools: one idea per line, with color and column choices. Paste spreadsheet cells as sticky notes, an editable table, or plain text; paste cell ranges into the table editor to replace and expand an existing range.
- Drag images and files onto the canvas; multi-image uploads and file drops form one undoable batch. Other files become downloadable attachments. A single dropped PDF, PowerPoint, Word, Excel, CSV, text, or Markdown file opens **Import document**.
- Embeds of Google Docs, Sheets, Slides, Forms, Drawings, Drive, and Calendar, YouTube, Vimeo, Microsoft Forms and Office viewer links, Figma, Loom, Miro, and other HTTPS pages, shown as preview cards that open live on demand. Google Sheets import as refreshable editable tables, Google Docs as sticky-note outlines, and Google Slides as frames. See [Embeds, Google Workspace, and document import](#embeds-google-workspace-and-document-import).
- Undo/redo, keyboard shortcuts, a keyboard-accessible object list, and named modal dialogs.
- English and French interfaces and templates, with a saved language preference.
- Light, dark, and system themes. System is the default and follows OS changes.
- Export the entire board, selected objects, a drawn region, or chosen frames from **Export board**. Every export runs in the browser; nothing is uploaded.
  - **PDF**: Letter, Legal, Tabloid, A4, A3, or a page sized to fit the content; automatic, portrait, or landscape orientation; narrow, normal, or wide margins; and a scale of readable detail, fit each area on one page (the default for frames, one page per frame), or 25% to 200% (100% prints one board pixel as one CSS pixel). Large areas split across pages at a constant scale, leaving out pages no object reaches, with an overview page that draws the numbered page grid, corner trim marks, labels pointing to adjacent pages, and footers such as "Page 3 of 12, row 2 column 1"; the overview's parts and the page labels go to those pages when clicked, and several frames or areas are bookmarked by name. The dialog previews the page count and, when an area would need more than 150 pages at readable detail, says how much smaller its detail is shown and suggests exporting frames or a region. Image rendering (the default) matches the board exactly. Vector rendering draws notes, shapes, frames, connectors, tables, cards, tags, and text as PDF paths and selectable text in standard PDF fonts, embeds PNG/JPEG images directly with their crop, and rasterizes only individual objects those fonts cannot represent (for example emoji or non-Latin scripts) or WebP images, keeping their stacking order.
  - **PowerPoint slides (.pptx)**: one 16:9 slide per frame, or one slide for the board or selection; a frame drawn in the slide's shape, such as a 16:9 frame format, fills its slide without the frame's outline, with the frame title kept just above the slide for the outline and screen readers, and frames that are all 4:3 make a 4:3 deck; a board or selection too large to read on one slide gets an overview slide, linked to a slide for each part that holds something, as PDF readable detail does. Each slide has a high-resolution image of the area, the frame title as the slide title, the frame text in speaker notes, and alternative text on each image. Link cards, embed cards, and linked words on a slide stay clickable. Opens in PowerPoint, Keynote, and Google Slides.
  - **SVG**: a vector image with selectable text, font families, sizes, emphasis, alignment, colors, and highlights; custom shapes, connectors with their dash styles, caps, and labels; drawings, frames, tables, cards, tags, rotation, and embedded images with crops and oval masks. Link cards, embed cards, and linked words stay clickable. Line breaks follow the canvas layout. Several frames are stacked in one file.
  - **PNG/JPEG**: one image per region, at up to 64 megapixels and 16,384 pixels on the longest side (16.7 megapixels on touch screens, the iPhone and iPad canvas limit); a browser that cannot make a canvas that large gets a 4,096-pixel image. Several frames download as a ZIP file with one numbered image per frame (up to 50 frames).
  - **Excel (.xlsx)** and **CSV**: an Objects sheet with one row per text-bearing object, and per image or drawing with a description (type, text, frame, tags, color, position, size, URLs of the object and its linked words, and ID), one sheet per table with typed numbers and dates, and a Frames sheet. Objects with task details gain a column per field used (assignee, start and due dates, status, priority, and Jira issue), and ISO dates become spreadsheet dates, so timeline and Gantt boards export usefully. CSV follows RFC 4180 with a UTF-8 byte order mark for Excel, exports the objects list, frames, or a chosen table, and prefixes cells that spreadsheets would evaluate as formulas. An area with nothing to list is refused with a message rather than downloaded as an empty sheet.
  - **Whiteboard file (JSON)**: an editable backup that can be imported again.
- Automatic local recovery versions and named checkpoints, with restoration from Version history.
- Local autosave in IndexedDB, plus opt-in file saving to the user's Puter drive.

The board, selection overlays, thumbnails, presentation slides, and exported visuals all use Canvas 2D. PDF pages embed raster images by default, with an invisible copy of the board text over them so it can be searched, selected and read aloud; vector rendering draws the text itself. Both carry the descriptions of images and drawings as hidden text, and keep link cards, embed cards, and linked words clickable. JSON exports retain editable objects. For a selected region, JSON includes complete objects whose bounds intersect that region, while image and PDF exports crop to its edges. On screen, SVG is used for interface icons, library previews and tiles, administrator charts, and the Tasks timeline; SVG, vector PDF, and spreadsheet exports reuse the canvas text layout and shape geometry. Office files are written with a small built-in ZIP writer, without extra dependencies. The renderer scales backing buffers for device pixel ratio and performs geometric hit testing for strokes, shapes, and resize handles. PNG/JPEG exports fall back to 4,096 pixels on the longest side only when the browser cannot make a larger canvas. Several frames export as a ZIP file of images; PDF, PowerPoint, SVG, and spreadsheet exports hold multiple frames in one file.

## Templates and content libraries

Open **Template library** from the library home, the **Templates** button in the tool rail (on phones, More tools), More tools, or command search. Search matches names, descriptions, categories, and keywords in English and French, ignoring accents; category buttons filter to Agile, Product planning, UX/UI design, Service design, Strategy, Workshops and facilitation, Analysis, Project management, Diagramming, or Playbooks. Previews paint as they scroll into view. Arrow keys move from the search field into the results and between cards; tabs support Left/Right, Home, and End. On a board, templates insert at the viewport center as ordinary editable objects; from the library home they create a new board.

The 58 templates combine frames, headings, prompts, and example content from realistic service scenarios, with tables, shapes, and connectors where they fit:

- **Agile (12):** Scrum board, Kanban board with WIP limits and an expedite lane, sprint planning, sprint review, sprint retrospective, Start/Stop/Continue, Mad/Sad/Glad, 4Ls, Sailboat, daily stand-up, backlog refinement, user story map.
- **Product planning (5):** Now/Next/Later roadmap, quarterly roadmap, OKRs, impact/effort prioritization matrix, RICE scoring.
- **Project management (4):** Gantt chart with a week header, swimlanes, duration-sized task bars with start and due dates, status, and dependencies as task metadata, milestones and dependencies; dependency map; RACI chart; risk register with heat map.
- **UX/UI design (9):** UX research canvas, personas, empathy map, design thinking process (empathize, define, ideate, prototype, test), user flow, mobile wireframe, desktop web page wireframe, usability testing synthesis, design critique.
- **Service design (4):** customer journey map with emotion curve, service blueprint with frontstage/backstage lanes and lines of interaction, visibility and internal interaction, ecosystem map, stakeholder map.
- **Strategy (6):** strategy canvas, lean canvas, business model canvas, SWOT with TOWS, PESTLE, logic model (theory of change from inputs to ultimate outcome, with assumptions, external factors, and indicators).
- **Analysis (4):** affinity mapping, fishbone (Ishikawa), 5 whys, weighted decision matrix.
- **Workshops and facilitation (10):** brainstorming, Crazy 8s, icebreakers, workshop agenda, four facilitator playbooks (project kickoff, Lightning Decision Jam, retrospective facilitation, and service design discovery), and two decks of 16:9 slides for presenting work and onboarding a new teammate, each slide with its own heading because presenting leaves frame titles out. Playbook steps are ordered frames with a duration and facilitator script, so **Frames and navigation** and presentation mode walk through the session step by step alongside the workshop timer.

## Tasks and planning

Select sticky notes, shapes, or text and choose **Task details** on the selection toolbar (or search for it in the command palette) to turn them into tasks. The panel sets status (To do, In progress, Blocked, Done), assignee, start and due dates, and priority for every selected object at once; mixed values show as Mixed. Each change is one Undo step, locked objects and read-only roles can view but not change details, and Escape closes the panel. On shared boards the assignee list shows the board's members; organization administrators on an organization board also see everyone in the organization; personal boards accept any name. **Task card** in the Shapes library, More tools, or the command palette adds a sticky note that is already a task.

Tasks show a compact footer inside the object: a status chip whose icon shape differs per status (ring, half ring, barred disc, check) next to its name, the assignee's initials, the due date (highlighted with an alert icon when overdue), and the Jira key when linked. The footer scales with the object and zoom, keeps light chips with dark text in both themes, and is included in PNG, JPEG, PDF (image and vector), and SVG exports.

The **Tasks** button in the canvas navigation (next to Tags), More tools, and the command palette open the Tasks view. It summarizes counts by status, overdue and blocked tasks, completion, and tasks per assignee, and lists every task with filters (status, assignee, frame, overdue, blocked), grouping (status, assignee, frame), and sorting by due date, start date, or name. Selecting a task closes the view and focuses it on the canvas. **Export CSV** and **Export Excel** save the filtered list (the workbook adds a summary sheet); the board's Excel/CSV export also reads task fields as columns and, when the exported area holds tasks, adds the same Tasks sheet with assignees, blockers and predecessors. The **Timeline** tab draws one bar per dated task from start to due date, grouped by assignee, frame, or status, with a today marker and dashed dependency lines. Bars are buttons: arrow keys, Home, and End move between them and Enter focuses the task. **Show as table** presents the same data as a table, and status never relies on color alone. **Place on board as timeline** adds an editable frame with a date header, lanes, and bar shapes that link to their tasks. It shows the tasks as they were when placed; **Refresh timeline**, in More options when the timeline or anything in it is selected and in the command palette, draws it again in place from the current tasks as one undo step, with the same lanes, title, and position, keeping objects added inside it and connectors to bars whose tasks remain.

Select a connector between two tasks and choose **Dependency** on its toolbar: "Start blocks end" or "Start depends on end". Tasks whose predecessors are not done appear as blocked, with a **Blocked by** column in the list; CSV and Excel exports also have a **Predecessors** column listing every predecessor, finished or not, as in a Gantt chart. Turn on **Update task status when a task moves into a frame named after a status (Kanban)** in the Tasks view, or **Turn on Kanban status sync** in the command palette, to let frames titled To do, In progress, Blocked, or Done (or À faire, En cours, Bloqué, Terminé) set the status of tasks moved into them. Turning it on also gives tasks already in such a frame that are still to do that frame's status, in the same undo step; a status someone chose, such as Blocked, is kept. The setting is saved with the board and is off by default, except on boards made from the **Kanban board** and **Scrum board** templates, whose cards are tasks with their column's status and follow the columns they are moved to. When a task is assigned to a member of a shared organization board, that member receives an assignment notification and the organization audit log records it.

On an organization board whose organization has enabled Jira (Organization settings, Integrations), **Send to Jira** in the task panel or the Tasks view creates one issue per selected task in the organization's project through the organization worker and stores the issue key and link on the object; **Refresh Jira status** copies each linked issue's current status back and, when it has changed, sets the task's status to match Jira's status category (To do, In progress, or Done; a task marked Blocked stays blocked while the issue is in progress). Credentials stay on the worker. On personal boards, boards on another server, or when Jira is not configured, the controls explain what is needed.

## Embeds, Google Workspace, and document import

**Embed content** (More tools, command search, or pasting a supported link) adds a resizable embed object. On the board it is a lightweight preview card with the provider badge, title, and address, so large boards stay fast and every export (PNG, JPEG, PDF, SVG, PowerPoint) stays static. Select the card and choose **Open live**, press Enter, or double-click to load the interactive content in a sandboxed iframe placed over the canvas. Live embeds follow pan and zoom, and close when scrolled out of view, when another object is selected, or with Escape, so one is open at a time. **Object properties** edits the title or link.

Supported services, each normalized to its official embed address:

- Google Docs, Sheets (including a sheet tab), Slides, Forms, Drawings, Drive files and folders, published ("Publish to the web") documents, and Google Calendar.
- YouTube (privacy-enhanced `youtube-nocookie.com` player, including start times) and Vimeo (including unlisted links).
- Microsoft Forms, Office Online viewer links (`view.officeapps.live.com`), and OneDrive embed links.
- Figma files, designs, prototypes, boards, and slides; Loom videos; Miro boards.
- Other public HTTPS pages, when the page allows framing. Local, private, and bare IP addresses are refused.

Only HTTPS addresses qualify; `javascript:`, `data:`, `blob:`, embedded credentials, and nonstandard ports are rejected. Boards store a canonical URL and provider, and the iframe address is always derived again from that URL, so an edited file cannot point an iframe elsewhere. Frames use `sandbox` (scripts, forms, and popups; never top navigation), a restrictive `allow` list, and `referrerpolicy` (`no-referrer`, or `strict-origin-when-cross-origin` for video players and design tools that verify the embedding site). The application never frames its own origin. Viewers of a Google embed must have access to the underlying Google file; Google shows a sign-in or access request otherwise.

Pasting or dropping a link to a supported service offers **Embed** or **Link card** (and **Import as table** for Google Sheets, or **Import as sticky notes** for Google Docs). Other links still become link cards directly.

**Google Workspace** (More tools or command search) works beyond embedding. It needs the file shared with "Anyone with the link" or published to the web, and fetches only Google's public export endpoints: directly, as Google allows for files shared by link, and through Puter's CORS-free `puter.net.fetch` only when a direct request is refused and the user is signed in:

- **Editable table from Google Sheets** reads `https://docs.google.com/spreadsheets/d/<id>/export?format=csv&gid=<gid>` for the linked tab and creates editable tables. Tables keep their source as a Google Sheets link with the A1 range (for example `…/edit#gid=0&range=A1:L20`). Select one and choose **Refresh from Google Sheets** (on-canvas button or command search) to re-read that range as one undoable change; the last table of a split import grows with new rows.
- **Google Doc outline as sticky notes** reads the document's Markdown export (plain text for older documents): headings become frames and each paragraph or bullet becomes a sticky note.
- **Google Slides as frames** downloads the presentation as PowerPoint (`/export/pptx`) and imports it like a .pptx file: one frame per slide with its title, text, tables, images, and speaker notes.
- Each import's first frame links back to the Google file. Private files return a clear sharing message. Organizations can turn Google integrations off (`Allow Google Docs, Sheets, Slides, and Drive embeds and Sheets import`), which hides the paste choice and blocks Google embeds and imports; turning off embedded web content blocks the other providers and generic pages.

**Import document** (toolbar button beside Add image, More tools, command search, or dropping a single document) extracts content into editable objects inside new frames, keeps the original as a downloadable attachment (up to 10 MB; optional), and adds everything as one undoable batch. The dialog shows progress, can be cancelled at any point without changing the board, and ends with a summary of what was imported and skipped. **Attach without importing** keeps the previous attachment behavior. Several files dropped or pasted at once become attachments; an attached document's **Import contents** (in its file card's properties) imports it later, beside the card.

| Format             | Result                                                                                                                                                                                                    | Limits                                                                                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| PDF                | Each page rendered to an image in a frame grid; optionally the page text as sticky notes beside each page                                                                                                 | 50 MB, up to 50 pages per import (5 to 50 selectable)                                  |
| PowerPoint (.pptx) | One frame per slide titled with the slide title; text boxes as sticky notes; slide tables and charts (title, series, and values) as tables; PNG, JPEG, and WebP pictures; speaker notes                   | 50 MB                                                                                  |
| Word (.docx)       | Top-level headings start frames; deeper headings become bold text; each paragraph or list item is a sticky note, keeping its list or heading number; tables, charts (as tables of their data), and images | 50 MB                                                                                  |
| Excel (.xlsx)      | Sheet picker (visible sheets or all); values, booleans, and dates as editable tables, numbers shown in their cell's number format (decimals, thousands separators, currency, percentages, leading zeros)  | 50 MB, first 1,000 rows and 120 columns per sheet                                      |
| CSV and TSV        | Editable tables; comma, semicolon, tab, or pipe detected; UTF-8 or Windows-1252                                                                                                                           | 5 MB                                                                                   |
| Text and Markdown  | One sticky note per line or bullet; Markdown headings start frames, tables become tables, and formatting is reduced to plain text                                                                         | 2 MB of text; Markdown files up to 20 MB, since pictures saved inside them are dropped |

Board tables hold 20 rows, 12 columns, and 2,000 characters per cell. Larger ranges are split into several tables (the header row repeats in each) or, if chosen, only the first 20 rows and 12 columns are imported; cells over 2,000 characters are shortened and counted in the summary, and up to 40 tables are created per sheet. Imports respect the 5,000-object board limit (frames are kept and further objects are skipped with a notice), the 5 MB and 40-million-pixel image limits, and the 10 MB attachment limit. Other image formats inside Office files (such as EMF, WMF, GIF, or SVG) are skipped and listed by type. Older binary formats (.doc, .ppt, .xls) are not supported.

All imported content is untrusted: text is inserted as plain text and never parsed as HTML, images are accepted only after their bytes are identified as PNG, JPEG, or WebP, and Markdown images and links are never fetched. Office files are read by a small built-in ZIP reader (`src/unzip.js`) that uses the browser's `DecompressionStream("deflate-raw")`; it limits archives to 2,000 parts, 50 MB per part, and 200 MB inflated in total, and stops inflating as soon as output exceeds the declared size. XML parts are parsed with `DOMParser` after refusing any `DOCTYPE` or `ENTITY` declaration. Browsers without `DecompressionStream` get a message to update. PDFs are rendered by pdf.js, loaded only when a PDF is imported, with scripting, XFA forms, and `eval` disabled and no remote font or character map requests; fonts a PDF does not embed use local substitutes. Password-protected documents are refused.

## Storage and cloud behavior

Boards, recovery versions, and reusable content are kept locally in IndexedDB. Theme, language, navigation mode, minimap visibility, recently opened board IDs, and the last copied object style use localStorage. Clearing site storage removes this local content, so export or save to Puter for a separate copy. Local deletion moves a board to Trash and leaves the cloud copy intact. Open the board in Trash to restore it. A board open in two tabs refuses a save over the other tab's edits; a star, a move to the trash, or a restore made in another tab stays through this tab's saves, and a board deleted permanently elsewhere does not return.

Version history retains the 30 most recent snapshots per board, plus the latest one of each quarter hour of the last 30 days (up to 200 more), within an approximate 50 MB budget; the latest snapshot is always retained even if it exceeds that budget. Restoring a version saves the current content first. Recovery versions and reusable content stay on this device and are not included in cloud saves or board exports.

From a canvas, **Save to Puter** signs in if needed and writes `whiteboard/<board-id>.json` in the app's Puter directory. Further edits to that board autosave to Puter during the connected session after a 1.5 second idle period. A serialized write queue prevents older requests from finishing after newer saves. Local saves continue if cloud saving fails. The save indicator distinguishes local, pending, cloud, and failed states. Closing the page while cloud work remains triggers the browser's unsaved-work warning.

The library and the editor show the account in their top-right corner: a **Sign in** button while signed out and, once signed in, an avatar with the account's initial that opens the account menu with the username, **Cloud boards**, and **Sign out**. Signing in from anywhere, including Save to Puter, Share board, or the AI assistant, updates it. Open **Cloud boards** to retrieve a saved board; a signed-in account sees its list at once. Board files are downloaded only when opened. A small `whiteboard/catalog.json` file supplies board names and IDs; its contents are updated only when a board is added or renamed. Personal backups do not use KV. Shared boards use a Puter worker, KV edit records, events, and peer connections. Images are embedded in board files, never in KV. Existing SDK authentication is reused. Sign out is offered only outside `puter.env === 'app'`, where Puter's desktop manages the session.

Personal cloud saving is explicitly opted into per session and remains a file backup. Choose **Share board** before editing across users or devices: shared boards use a Yjs merge protocol, a durable edit log, and peer activity. The current personal catalog is cached for the session.

## Collaboration

Use **Share board** from the canvas to choose the access a link gives (facilitator, which only the owner hands out, editor, commenter, or viewer) and whether it opens the entire board or one of its sections (frames), then copy the link. On an organization's board, people outside the organization who open a link join as guests where its policy admits guests, unless **Only members of the organization can join with this link** is chosen. Invitees sign in with Puter. **Board settings** sets who can open the board without an invitation: only invited people, everyone in the organization, or anyone signed in with the link, as the organization allows, each with its own role. The **Participants** button shows membership, when each guest's access ends, and lets the owner and facilitators change roles (facilitators below their own), renew a guest's access, or remove people. Access is not tied to whoever created the board: ownership can be transferred, and organization administrators govern every board. Invitations expire after seven days and **Reset link** withdraws them all; that does not remove existing members. The library also has **Join shared board** for pasted links. Guests and the organization policies that govern them apply to organization boards; a board shared from a personal account admits whoever its owner or facilitators invite.

Shared text is sent while typing; Escape finishes the editor. Undo affects this browser’s edits. Cursors, selections, and movement/drawing previews travel over peers; saved changes are acknowledged by the worker and recover through KV even when peer links or events fail. Unsent changes remain in IndexedDB. Media stays in Puter files and remains embedded in editable exports.

Owners and facilitators run facilitation sessions (votes, polls, private mode, locks, staged frames, and the agenda); editors and commenters vote, answer, and react; viewers watch, send live reactions, and raise their hand. The worker enforces these roles and records facilitation changes in the organization audit log.

See [the collaboration architecture and operating limits](docs/collaboration.md) for deployment, permissions, storage, recovery, transport details, and testing. The 512-session peer topology is unit-tested, but hosted-service capacity is not established. The initial implementation retains immutable edit records and recovery checkpoints; log compaction is not yet enabled.

Image uploads and clipboard images accept PNG, JPEG, and WebP up to 30 MB and 40 million decoded pixels each; one over 5 MB, such as a phone photo, is redrawn at most 4,096 pixels on its longer side (smaller if needed) as WebP, or JPEG where the browser cannot write WebP, so it fits the 5 MB a board image may take. Multi-file transfers support up to 20 files and 50 MB per batch. Failed batches add no partial content, and navigating away cancels pending insertion. File attachments accept up to 10 MB each and are embedded as downloadable binary data. JSON imports are limited to 100 MB and 5,000 objects, with geometry, drawing, text, color, and image validation before rendering. SVG uploads are intentionally unsupported. Large boards may need a modern desktop browser; offscreen objects are culled, but there is no spatial index. Frames contain objects that move, duplicate, and delete with them. Use Organize selection to group objects, assign frame membership, or connect exactly two shapes; the Arrow tool also supports independent arrows and lines attached at just one end. Touch supports one-finger panning, pinch zoom, tap selection, dragging selected objects, long-press selection, and direct drawing. Zoom buttons work on every device.

## Miro migration

`src/migration/` migrates boards from Miro through its REST API v2. `createMiroMigration(deps)` returns `{ open() }`, a dialog the host opens with an injected `fetch` (in production `puter.net.fetch`, which avoids browser CORS limits), `createBoard`, `deleteBoard`, `saveLog`, and `loadLog`. The conversion and planning modules never call Puter directly; `src/migration/host.js` connects them to the app. Open it with **Migrate from Miro** in the board library, from command search, or from Organization settings → Boards. Organization administrators migrate into shared boards on the organization's worker, keeping each board's owner and member roles by email; everyone else migrates into boards on this device, which do not take Miro owners or members (the log warns about each such board). The log is a file in the person's Puter drive.

- **Connect and inventory.** Enter a Miro access token (a password field kept only in the open dialog, or in memory until the page closes if chosen), an optional Enterprise organization ID, and the organization's email domains. The inventory lists every board visible to the token with its owner, team, members, roles, item count, sharing policy, and last modification. Organization member and team endpoints add email addresses and team names; on other plans (403/404) the dialog says so, and a pasted `Miro user ID, email` mapping or a fallback owner email fills the gaps. People whose email domain is outside the listed domains (subdomains included), or whom Miro marks as external or team guests, are flagged as guests.
- **Roles.** Miro owner stays owner, co-owner becomes facilitator, and editor, commenter, and viewer keep their names. `createBoard(board, { ownerEmail, members, source, asTemplate, signal })` receives the owner, each member's email, role, and guest flag, and the Miro source identifiers so the host can assign ownership and access.
- **Conversion.** Sticky notes, text, shapes (rectangles, ellipses, and the shape library, with a rectangle fallback), frames and their members, images (downloaded and embedded within the 5 MB/40-million-pixel limits, or a placeholder), cards and app cards (title, description, assignee, due date, and fields as note text), documents, embeds, and link previews (link cards, or attachments up to 10 MB), connectors (endpoints, straight/elbow/curved paths, dash styles, widths, caps, and captions), Miro Docs (HTML or Markdown content as formatted text), mind maps (from Miro's experimental mind map endpoint: branches, sides, sibling order, and node shapes, laid out automatically when Miro gives no positions), groups (including connectors, and groups Miro lists over several pages), tags (read per tag, since Miro items do not list their own; objects other than sticky notes keep them as a text line), colors, rotation, font sizes and families, alignment, bold/italic/underline/strike, text colors and highlights within text, links, and bulleted or numbered lists. Frame children are positioned from Miro's parent-relative centers. Every result passes the normal board validation.
- **Plan, dry run, and migrate.** Boards are grouped into phases by team, owner, or count, with a batch size. A dry run converts without saving and shows per-type counts, skipped objects with reasons, and warnings. Migration runs one board at a time with progress and cancellation; migrated boards are skipped on later runs unless re-migration is forced. What a migrated board still needs (an owner to assign, members without email, link or team sharing to turn on again) is listed beside its result, in English or French, as well as in the log. **Import as template** passes `asTemplate: true`.
- **Validation log and rollback.** Each board gets a log row (pending, migrated, failed, or rolled back) with the created board ID, owner, counts, warnings, error, and attempts, plus an event trail. The log is written through `saveLog` after every board, as a Puter file chosen by the host (never KV), and a failed save stops the run. Download the log as CSV (spreadsheet formula characters are neutralized) or JSON, or the inventory as CSV. **Roll back phase** asks for confirmation, deletes the boards created for that phase (including earlier forced copies), and keeps failed deletions for retry.

A board with more than 5,000 objects (Miro allows up to 100,000) is migrated as several boards named “Title (1 of 3)” and so on, each with the same owner and members; every frame, group and mind map stays whole on one of them, objects outside frames are divided by position, and a connector between two parts stays on the part it starts on with a free end. The log and validation report list every part (`part_board_ids`), and rollback deletes them all. Miro's REST API does not provide comments or the cells of tables. Every report says comments were not copied, and each table, and any other item type the migration cannot read, keeps its place and size as a placeholder linking to that item on the Miro board, listed in the report as skipped. When Miro refuses to list a board's groups, mind maps, or tagged items, the board is still migrated and its report names what is missing. Stencils, custom connector attachment points and bend points, shape borders, and text background colors are not migrated; frames are drawn as outlines, so a frame's background color is kept in its data but not shown, and the report names each colored frame; partly transparent fills are blended with white. Miro rate limits are respected, waiting for `Retry-After` or the announced credit reset, with retries for transient server errors.

## Accessibility

Open **More tools → Mouse, trackpad, and touch**, or search for it in the command palette. Auto-detect is the default; select Mouse or Trackpad if your device scrolls unexpectedly. Mouse mode uses the wheel to zoom toward the pointer. Trackpad mode uses scrolling to pan; pinch or Ctrl/Cmd-scroll zooms. Shift-scroll pans horizontally. Right-button, middle-button, and Space-drag pan in either mode. The preference persists locally and updates other open tabs.

On a touchscreen, drag the board to pan and pinch to zoom. Tap an object to select it, then drag the selection or its resize handle. Viewers and locked selections continue to pan. Hold for half a second, then drag to select multiple objects. Creation tools place an object when the tap ends; pen and arrow tools draw immediately. A second finger cancels an unfinished object move, stroke, connector, or region selection before navigating, preserving undo/redo. Lifting one finger continues panning; Escape, pointer cancellation, focus loss, or resizing stops active gestures. Finger input is ignored while a pen or mouse gesture is active.

Press M or use the map button to open the minimap. Click a location to center the board there, or drag the outlined visible area. While the map has focus, arrow keys pan (Shift moves farther), plus/minus zoom, 0 resets zoom, and Home/Enter fits the board. Escape cancels an active drag or closes the map. Across the editor, Ctrl/Cmd + Plus/Minus zooms, Ctrl/Cmd + 0 resets, Alt/Option + 1 fits the board, and Alt/Option + 2 fits the selection. A board spread wider than the furthest zoom out (1%) can show is fitted, here and on opening it, to the part holding the most objects, with a message saying the whole board does not fit. With no selection, arrows pan the canvas; with a selection, they continue to nudge objects. Text fields retain native shortcuts. Letter shortcuts read the letter a key types on Latin layouts (AZERTY, Dvorak) and the physical key on layouts that type another script (Cyrillic, Greek, Hebrew), so Ctrl/Cmd + Z undoes everywhere. The map uses cached silhouettes rather than text or media thumbnails, and moves aside for desktop search; narrow-screen search temporarily hides it.

Use **Comment (C)** to place a pin, **Add comment** on a selected object, or **Comments** to browse discussions. Object pins follow movement; deleting their object leaves the discussion at its last location. Drag a pin to reposition or attach it to another object. Focused pins support arrow keys (ten units with Shift). Shift+C toggles pins. Enter posts, Shift+Enter adds a line, and Escape closes while retaining a draft. Search and Open/Resolved/All filters locate discussions; selecting one centers its pin without changing zoom. Replies reopen resolved threads. Only the author can edit, delete, or restore their messages; viewers can read. Comment actions are separate from board Undo/Redo and recovery-version restoration.

Comments allow 500 discussions, 100 messages per discussion, 5,000 total messages, and 4,000 characters per message. The device keeps up to 20 unsent drafts in local storage; these are not shared. Delete comment retains its text for restoration, including in backups and shared history. Entire-board JSON exports and board duplicates retain comments; selected-object/frame JSON, object copies, image, PDF, slide, SVG, and spreadsheet exports, and presentations omit them. Local authorship uses a device identity; sharing adopts this device's comments into the signed-in account. Imported messages from other identities remain attributed to their original authors. Mention people with @name to notify them in the app and, when they have verified an email, by email; suggestions list the board's members and people present, and on a board shared with the whole organization, its other members too; replies notify earlier participants in the thread. Shared boards also offer a commenter role that can discuss content without changing it.

Ctrl/Cmd + F opens Find on board. Search is case- and accent-insensitive, finds objects holding every word typed in any order and across line breaks, includes complete table contents, file/link metadata, tag names, and the assignee and Jira issue on task badges, and can be filtered by object type. Enter/Down goes to the next result; Shift+Enter/Up goes to the previous result, and screen readers hear its position, kind, and text. On a phone, going through results shrinks the panel to the search and its arrows so the match shows below it; **Show results** or typing brings the list back. Click a result to preview its location, then Select on board to select it for editing (inside its group, when it is in one). Escape closes search. Previewing does not change the selection or undo history (the selection is set aside while Find is open, so keys pressed elsewhere cannot change it unseen, and comes back when Find closes), and locked objects remain protected. Search indexes authored content, not text embedded inside images or attachments. Inside text fields, Ctrl/Cmd + F retains browser search.

Ctrl/Cmd + C, X, and V copy, cut, and paste on the canvas. Inside text fields they retain native text-editing behavior. Plain text paste accepts up to 20,000 characters; object clipboard payloads are capped at 100 MB. Editable object transfer uses a custom clipboard format with an HTML fallback. Applications that strip both formats receive plain text; Miro’s private object format is not imported. Use **Copy as image** or Ctrl/Cmd + Shift + C to copy the selection as a PNG with a white background and a small margin. Frames include their contents, and connections between selected nodes are included. The image captures the selection at the time of copying, waits for fonts and embedded images, and is capped at 4,096 pixels on its longest side. Copying preserves locked content, selection, and undo/redo. Navigating away while the image is preparing cancels the copy. If clipboard access is blocked or unsupported, a preview offers PNG download and, when available, a fresh copy attempt. Ordinary copy/cut/paste keeps its editable-object behavior.

**Bulk sticky notes** accepts up to 5,000 nonblank lines, subject to the board’s 5,000-object capacity, and 20,000 characters per note. Spreadsheet paste recognizes HTML tables and tab-separated plain text (tab stops and list markers in text copied from Word or a web page stay text), including single-column tables, quoted multiline values, and merged cells (their covered positions become blank cells). It preserves blank positions and treats formulas as copied text or displayed values. Ranges are limited to 50 rows, 100 columns, and 1 million text characters (4 million HTML characters). Tables retain their existing limit of 20 rows, 12 columns, and 2,000 characters per cell; larger ranges can become stickies. Each import is one undoable change. Imported notes and table rows expand to fit their text. In the table properties dialog, spreadsheet paste replaces cells starting at the focused cell and expands the table within those limits; Save changes commits the range, and closing discards it. Ordinary multiline prose stays one text object on the canvas and uses native paste inside text fields.

**Cluster sticky notes** groups selected notes by color, tag, or one custom name. Open it from the selection toolbar, Organize selection, More tools, or the command palette. The preview shows how many frames and extra copies will be created. Notes with several tags appear in each matching cluster; untagged notes receive a “No tag” cluster. Clusters are editable frames: rename their titles, move them with their notes, resize their boundaries, or move notes between them. Notes leave previous groups/frames; other objects stay put. Clusters find nearby clear space, and the operation undoes in one step. Locks, viewers, geometry limits, and the 5,000-object cap are enforced; clustering requires notes outside mind maps. Concurrent text edits are retained, while layout or tag changes require reviewing the refreshed preview. The AI assistant can also group selected notes into named themes.

**Tags** organizes sticky notes with reusable labels and colors. Select notes and open Tags from the toolbar or command palette; create a tag, reuse an existing one, or toggle it across the selection. Typing a name in the search and pressing Enter applies that tag, creating it in the next color when the board has none by that name. Mixed selections show a mixed state. Find opens an exact tag filter in board search, and ordinary search also matches tag names. Rename, recolor, or delete a tag across the board, with Undo; locked tagged objects must be unlocked first. Notes support up to eight tags, with a board catalog of up to 1,000 tags and names up to 64 characters. Tags appear in a compact note footer; narrow notes show shortened labels and an overflow count, while the panel retains every label. Copy/paste and reusable content carry referenced definitions and reuse matching destination names. JSON backups retain the catalog; image/PDF exports, previews, and presentation include the visible tag labels. Shared tag membership merges independently and viewers can browse/search tags.

**Table cells** opens from the navigation controls, command palette, or Enter on a selected table. Click a selected table to select a cell, drag to select a range, or double-click a cell to edit it. Arrows move between cells; Shift extends the range. Enter or F2 edits, Tab advances, Shift+Enter inserts a line break, and Ctrl/Cmd+Enter saves without advancing. Escape cancels the current cell draft; a second Escape leaves cell selection. Copy/cut uses spreadsheet text and HTML; pasting one value fills the selected range, while a matrix replaces and expands cells from its top-left corner. Row and column menus insert or delete around the selection. Each saved edit, range operation, and structural change supports Undo. Locked tables and viewers can navigate and copy cells. Object properties retains the complete-table dialog. Cell drafts stay private until committed; conflicting remote edits or temporary access loss retain up to 100 drafts for this browser session, available by reopening the cell. Unsaved drafts do not survive a reload. See the [shared-table concurrency limits](docs/collaboration.md).

Drag a table cell border or the selected row/column handle to resize it. **Column width** and **Row height** apply to the selected range; **Fit to text** and **Equal sizes** adjust the selected tracks. Focus a resize handle and use the arrow keys for one-pixel changes, or Shift+arrow for ten pixels. Tab advances through cells and reaches the resize handles after the final cell; Shift+Tab from the first cell reaches the toolbar. Escape cancels a resize preview. Whole-table resizing scales the existing proportions. Custom sizes survive cell edits, row/column insertion, copy/paste, exports, saving, and Undo. Independent shared track resizes merge; structural edits still replace the matrix atomically.

**Mind map** starts a central node through More tools, command search, or the template library. Select the root and click a plus button to start a branch above, below, left, or right; child nodes offer a plus button in their branch direction. The buttons support keyboard activation and keep a 44-pixel hit area at every zoom level. Dragging away, Escape, and interrupted touch gestures cancel creation. Tab creates a child; Enter creates a sibling (a child when the root is selected), including while typing. Shift+Enter inserts a line, Ctrl/Cmd+Enter finishes typing, and F2 or double-click edits an existing node. Outside text editing, arrows navigate parents, children, and siblings; Shift+arrows retain precise movement. Select a parent to move, copy, or delete its whole branch. **Mind map controls** changes orientation, line style, and automatic layout. **Move mind map branch** searches for a new parent or detaches a branch into its own map; command search also offers **Move branch earlier/later**. Drag a branch onto another node to reassign it with all its descendants; a highlighted parent and drop hint preview the change. Dropping on a root’s edge chooses the new branch direction. The view shifts only when needed to keep the moved node and its new parent visible. Hold Ctrl/Cmd to move without reassigning. Escape, interrupted gestures, and conflicting changes to the moving branch cancel the drop; protected targets cannot be changed. Reassignment cannot create a cycle and undoes in one step. Moving a child without reassignment, or resizing it, switches its map to manual layout; moving the root retains automatic layout. **Layout nodes** tidies a manual map without enabling automatic layout. Copying a partial branch creates an independent manual map so its geometry is preserved. The existing 5,000-object limit includes nodes. **Collapse branch** hides descendants without changing their geometry. Hover a parent or select it to use the minus control; click its count to expand. Counts include hidden nodes and unresolved comment threads. Nested collapsed branches keep their state. The selection toolbar and command search provide the same controls; the forward arrow expands a collapsed node. Copy, move, delete, and undo still include the complete branch, and the toolbar identifies hidden selected objects. Search results, object links, Board objects, and comment threads reveal the path to hidden content. Adding or reassigning a branch opens its destination in the same edit. Collapse is saved and shared for editors; viewers can explore branches locally without changing board data. Find on board opens a collapsed branch holding a result only on this screen while stepping through results, and closes it again with the search unless the result is selected on the board. Active text drafts stay visible during a remote collapse, and hidden drag gestures cancel safely. Minimap, presentation, thumbnails, PNG/JPEG/PDF, and image copying follow collapse; Whiteboard JSON backups retain the full hierarchy.

Lock selected objects with the padlock button or Ctrl/Cmd + Shift + L. Click a locked object or find it in Board objects to unlock it. More tools → Unlock all objects clears all locks in one undoable action. Selecting a frame directly locks the frame without locking its contents; selecting all objects locks each selected object. Marquee and Select All skip protected content. Locked group members protect their group, and a locked child prevents moving or deleting its containing frame. Copy/duplicate preserves locks. Attached connectors continue to follow their endpoints; deleting a node attached to a locked connector requires unlocking that connector first. On a shared board, objects that an owner or facilitator locks stay locked for participants: only a facilitator can unlock, change, or remove them, and the worker enforces it. A participant's own locks stay theirs to remove, and **Unlock all objects** leaves facilitator locks and hidden objects alone.

Objects snap to visible edges and centers while dragging or resizing. While dragging, spacing guides also help insert an object between neighbors or extend an evenly spaced row or column. They compare edge-to-edge gaps, including unequal-sized objects and groups, and show matching gap measurements when there is room. Only nearby neighbors in a shared row or column contribute; overlapping content interrupts a spacing suggestion, and a closer edge/center alignment takes priority. The magnet beside Undo toggles snapping and remembers your preference on this device. Press Alt/Option during a move to bypass snapping temporarily; holding it before starting a move drags a copy. Alt/Option also bypasses snapping while resizing. Guides use a constant screen-space tolerance across zoom levels. Each move/resize is one undo step; Escape or a cancelled pointer gesture restores the original geometry without consuming undo/redo history. Keyboard nudges stay precise and do not snap.

**Grid and snapping** offers dots (the default), lines, or no background grid. Enable **Snap to grid** to align canvas creation, pasted/dropped batches, movement, and resize edges to the visible grid; grouped content retains its relative layout. Grid spacing starts at 24 board units and becomes coarser at low zoom to match what is visible. Object alignment guides take priority. Hold Ctrl/Cmd or Alt/Option during a move, resize, or canvas creation to bypass the grid; free connector endpoints also snap unless attached to an object or constrained with Shift. Proportional resizing retains its ratio, auto-height text retains its derived height, and numeric dimensions and keyboard nudges remain exact. Automatic diagram layouts keep their own spacing. Choosing no grid turns grid snapping off. These preferences are shared across this device's tabs, do not enter board Undo or exports, and can be changed by viewers without granting edit access.

Drag the shared bottom-right handle to resize a group or selection, including its spacing and text. Groups and images preserve proportions by default; hold Shift to toggle this behavior. Use Resize selection for numeric width/height, proportion locking, and optional text scaling. Selecting a frame directly resizes only its boundary; selecting its contents together scales the layout. Ctrl/Cmd + Alt/Option + Shift + Plus/Minus resizes proportionally in 10% steps. Size limits keep text readable and geometry within supported bounds.

**Object dimensions**, also available through command search, displays the selected width and height in board pixels independently of zoom. Locked content and viewers can use the readout. With **Snap to objects** enabled, resizing within six screen pixels of a visible object's width or height matches that dimension and shows paired measurement guides. Groups provide one combined reference size; closer edge/center alignments take priority, with alignment winning ties and grid snapping used as a fallback. Alt/Option bypasses matching. Proportional resizing preserves the ratio, and automatic-height text matches width only. The setting is off by default, stays local across reloads and tabs, and does not change board history or exports. A changed setting in another tab cancels an unfinished resize safely.

Select one image and choose **Crop image**, double-click it, or use the command palette. Drag the crop area or any of its eight handles; choose an aspect ratio or an oval mask, and expand **Exact crop (pixels)** for numeric boundaries. Focused handles support arrow keys (one source pixel, or ten with Shift); Shift while dragging keeps proportions, and Alt/Option bypasses alignment snapping. Wheel navigation follows the selected Mouse/Trackpad preference. Apply with the button, Enter on a handle, or a click on the surrounding board. Escape or Cancel discards the draft. **Reset original** reveals the full source at its current scale. Cropping retains the original image data, and shared locks, geometry changes, deletion, or lost editing permission close stale drafts. Batch shape cropping, borders, and corner styling remain future work.

**Replace image** is available on the image toolbar, in More tools, and through command search. Choose a PNG, JPEG, or WebP from your device, another image on the board, or a direct HTTP/HTTPS image URL, then review the preview and apply. Replacements fill the current area without stretching; board sources reuse their visible crop. Position, size, rotation, oval masks, names, groups, links, and comments remain. Use **Crop image** to adjust or reveal the new source. Replacement undoes in one step; cancellation and unchanged results preserve Redo. Images up to 30 MB and 40 million pixels are accepted; one over 5 MB is made smaller, as uploads are. URL loading depends on the source site's browser access rules; download and upload the file if direct loading fails. Changes to the destination or its edit permissions close stale previews. Stock-image libraries remain further work.

Use Organize selection for alignment, distribution, and layers. Alignment needs two independent objects/groups; distribution needs three and holds the outer objects in place. Groups and frame contents retain their internal spacing. Ctrl/Cmd + [ or ] sends content one layer backward or forward; add Shift to send it to the back or front. Frames stay behind content.

Use the Arrow tool (A) to drag between shapes, notes, cards, or images. Attached ends follow their objects, including locked nodes. Select a line to change its path, stroke, thickness, or either cap. Double-click or press Enter to edit its centered multiline label. Drag the round endpoint handles to reconnect; hold Alt/Option for a free endpoint, or Shift to constrain free endpoints to 45-degree angles. Object properties opens keyboard-accessible endpoint choices. Escape and pointer cancellation restore the previous connection without consuming undo or redo. Labels use the same typography controls as other text and remain included in search, clipboard, and export. Lines currently have one centered label and automatic routing; custom bend points, multiple labels, and obstacle avoidance remain gaps. Selected shapes also expose quick-connect handles for connected creation and nearby-node connections.

Ctrl/Cmd + B, I, and U toggle bold, italic, and underline. While editing, they format the selected words or the next text typed at the caret. Outside text editing, they apply to the selected objects.

Controls have accessible names, visible keyboard focus, and appropriate pressed/disabled states. Dialogs use native focus containment, Escape dismissal, and focus restoration. Canvas objects have a parallel accessible HTML outline and can also be selected through **Board objects**, both listing each frame (in presentation order) followed by what it holds, then the objects outside frames. Each is one Tab stop: arrow keys, Home and End move within it, and Page Down and Page Up move between frames. Board objects sets a frame's objects in under it, finds a frame by its name with everything it holds, and lists at most 300 objects: every frame, each with an even share of its objects. Choosing an object brings it into view: Board objects frames it, and the outline pans only when its middle is off screen, keeping the zoom unless it does not fit. Arrow keys then move the selected objects and Enter opens their editor. **Frames and navigation** keeps focus on the frame's row as it goes there and says which frame it showed (for example "Showing frame 2 of 12: Ideas"), marks the frame in view with `aria-current`, and closes with Escape, returning focus to its button. Text inputs do not trigger canvas shortcuts. Motion respects `prefers-reduced-motion`. Images take alternative text from Object properties or the command palette (with an optional AI suggestion); it is read in the object outline and Board objects. See the [accessibility conformance report](docs/accessibility.md).

## App identity

The original artwork is `icon.png` at the project root. Run `npm run icons` to regenerate the UI images, PNG/ICO favicons, Apple touch icon, and padded maskable icon in `public/`. `public/manifest.json` supplies the app name, launch settings, and launcher icons.

The icon’s blue (`#238cfd`) is the brand and browser theme color. Interface accents use darker blue in light mode and lighter blue in dark mode to maintain readable text and controls.

## Dependencies and resources

See [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Fonts and icons are bundled locally. The only external runtime script is the official Puter.js SDK at `https://js.puter.com/v2/`. pdf.js (`pdfjs-dist`, legacy build) is bundled as a separate chunk with its worker and its WebAssembly image decoders for scanned pages, and is downloaded from the application's own host only when someone imports a PDF.
